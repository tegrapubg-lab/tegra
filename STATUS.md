# STATUS — Tegra Flow v0.1.0

Обновлено в конце сессии разработки. Разделы: что реализовано → что реально запускалось → что НЕ проверено → ограничения → следующий шаг.

## Реализовано

* **Оболочка Electron** (`src/main`): окно, трей (открыть / статус / автозапуск / закрытие в трей / полный выход), единственный экземпляр,
  автозапуск при входе в Windows (`--hidden`, по умолчанию выкл.), различие «закрыть окно» ≠ «выйти полностью» с предупреждением,
  мастер-ключ через `safeStorage` (DPAPI), запуск движка как `utilityProcess`, автоперезапуск при падении, корректная остановка,
  данные в `%APPDATA%\Tegra Flow`, ручные и ежедневные резервные копии, восстановление.
* **Движок** (`src/engine`): SQLite (`node:sqlite`) + миграции; устойчивая очередь заданий (lease, heartbeat, `rerun`, уникальность задания на запуск);
  исполнитель графа (ветвление, независимые ветки, пропуск мёртвых веток, явное слияние, списки, тайм-ауты, повторы с задержкой,
  `onError: continue`, отмена, лимиты параллелизма, лимиты размера, неизменяемый снимок сценария); ожидание/подтверждение/вложенный сценарий
  хранятся в БД; восстановление после падения; расписания (интервал/cron, IANA-пояс, политика пропущенных запусков); webhook с секретом;
  Telegram long polling (один получатель на токен, офсет в БД); адаптеры LLM (OpenAI-совместимый, Anthropic, Демо); агент с инструментами и лимитами;
  защита от SSRF; шифрование и маскирование секретов; локальный HTTP API (127.0.0.1, Bearer, проверка Host).
* **Узлы (все 14 запрошенных + служебные):** ручной запуск, Webhook, Расписание, HTTP, Поля, IF, Switch, Разделить список, Объединение, Ожидание,
  Вложенный сценарий, Telegram (получить/отправить текст и файл), Языковая модель, ИИ-агент, Ждать решения; плюс «Повторить N раз», «Результат сценария».
  У каждого: спецификация параметров (из неё строится форма), валидация, исполнитель, краткое описание результата (`summary`).
* **Интерфейс** (на русском): список сценариев (создать, открыть, запустить, дублировать, импорт/экспорт JSON, удалить), редактор на React Flow
  (добавление/соединение/перемещение/удаление узлов, масштаб и панорама, миникарта, форма параметров, проверка обязательных полей и связей,
  запрет циклов при соединении, статусы на холсте, входы/выходы/журнал/ошибки каждого шага, история запусков, восстановление несохранённых правок
  и положения холста после перезапуска), запуски, подтверждения, подключения, примеры, настройки.
* **Примеры** (`examples/*.json`, также в разделе «Примеры»): основной сценарий IF→HTTP, бизнес-пример «одежда → 3 агента → подтверждение → Telegram»,
  Telegram-эхо, Webhook-приём, проверка сайта по расписанию.
* **Документация:** README.md, PLAN.md, этот файл.

## Что реально запускалось и проверялось (в этой среде, Linux)

* `npm run typecheck` — без ошибок.
* **69 автотестов (vitest), все проходят** (`npm test`):
  * ветвление/слияние (append, zip, requireBoth), Switch, Split, Repeat, параллельные ветки, выражения и их безопасность, валидация графа/циклов;
  * retries (3-я попытка успешна, одинаковый Idempotency-Key), исчерпание попыток, `onError: continue`, тайм-аут узла;
  * отмена выполняющегося запроса, отмена ожидающего запуска с каскадом на вложенные;
  * Ожидание в БД и продолжение после «перезапуска» движка; подтверждение (продолжить / отклонить / тайм-аут); вложенные сценарии, рекурсия ограничена;
  * неизменяемость снимка; защита от двойного захвата (два воркера, 30 заданий); просроченный lease; восстановление `running`-запуска без задания; лимит параллелизма;
  * **реальный процесс движка и `kill -9` посреди HTTP-узла → перезапуск → запуск завершился, выполненные узлы не повторялись**; замок одного экземпляра;
    Wait переживает перезапуск процесса;
  * cron/часовые пояса (Стамбул, Нью-Йорк с летним временем), «сон» (skip / runOnce — ровно один запуск), расписание переживает перезапуск;
  * SSRF (таблица адресов, обфусцированные формы, перенаправления, лимит размера), AES-GCM, маскирование (выход, ошибки, файлы БД+WAL, API, экспорт),
    webhook (401/405/202/404/429), API-токен и Host, миграции и резервная копия;
  * Telegram на локальном mock Bot API (получение, офсет, фильтр chat id, ответ, файл multipart, один бот — один сценарий, ошибка без токена);
  * агенты на «скриптованной» модели (инструмент, неразрешённый инструмент, лимиты шагов/вызовов/токенов, JSON с исправлением, вложенный сценарий как инструмент),
    цепочка агентов на демо-провайдере, адаптеры OpenAI-совместимый и Anthropic на mock-серверах;
  * бизнес-пример целиком (до подтверждения в Telegram ничего не уходит; «продолжить» → отправка; «отклонить» → нет; TikTok помечен `not_connected`);
  * импорт всех `examples/*.json`.
* **Сквозной тест настоящего окна Electron** (`scripts/ui-e2e.cjs`, Playwright + xvfb), пройден и на исходниках, и на упакованном `app.asar`:
  `contextIsolation/sandbox` включены, `nodeIntegration` выключен, в странице нет `require/process`, неразрешённый IPC-метод отклонён;
  сценарий **собран мышью** (5 узлов, 4 связи перетаскиванием), параметры заполнены через форму, валидация показывала ошибки до настройки и «пройдена» после,
  Ctrl+S; запуск «с данными» → очередь → фоновый процесс → **реальный HTTP-запрос** на локальный сервер (`{"total": 42}`), ложная ветка IF пропущена,
  входы/выходы шага видны; **перезапуск приложения** — сценарий и история восстановились из SQLite; закрытие окна скрывает его, движок продолжает отвечать;
  «Полный выход» штатно завершает движок и снимает замок.
* Собран Windows-каталог приложения `release/win-unpacked` (**настоящий `Tegra Flow.exe`**, PE32+ GUI x86-64, `app.asar` с движком/main/renderer).
  Скриншоты UI просмотрены.

## Что НЕ проверено / не выполнено

* **Установщик `Tegra-Flow-Setup-0.1.0.exe` в этой среде НЕ получен.** electron-builder собрал каталог приложения, но финальный NSIS-шаг требует `wine`,
  который в песочнице не запускается (зависает при создании префикса). Собирайте на Windows: `npm install && npm run dist:win`, либо
  GitHub Actions workflow `windows-installer` (не запускался). Установка из `.exe`, создание ярлыка на рабочем столе, запуск на чистой Windows **не проверены**.
* **Не проверялось на Windows:** DPAPI (`safeStorage` — в Linux-проверке ключ хранился файлом), реальный значок в трее, автозапуск при входе (`setLoginItemSettings`),
  Windows-уведомление при первом закрытии, SmartScreen, поведение при выключении/сне ПК (логика «сна» проверена тестами с подменой часов).
* Диалоги выбора файла (экспорт/импорт/резервная копия/восстановление) и подтверждение «Полный выход» при активных сценариях не прогонялись автоматически
  (код написан; вызов `app.quit` без активных сценариев проверен).
* **Внешние сервисы:** настоящие OpenAI/Anthropic/Telegram не вызывались (нет ключей) — проверено на локальных mock-серверах, повторяющих формат API.
  Фактическое поведение у провайдеров (лимиты, формат ошибок) может отличаться.
* Нагрузочные испытания и многочасовая работа не проводились.

## Ограничения (сознательные)

* Нет узла произвольного кода (нужна настоящая изоляция); нет монтажа видео и публикации в TikTok (показываются как «не подключено»).
* Доставка внешних действий — at-least-once; exactly-once не обещается.
* Webhook отвечает асинхронно (202 + runId), синхронного ответа с результатом нет. Публичный доступ — только через собственный туннель.
* Telegram: только входящие текстовые сообщения (+подпись к медиа), только long polling; один токен — один сценарий; отправка файла — по URL или «текст как файл».
* Switch — максимум 4 правила; агент — только встроенные инструменты и вложенные сценарии (нет MCP).
* Секрет, вписанный в параметр узла вручную, хранится в сценарии открытым текстом (маскируется при показе/экспорте) — используйте «Подключения».
* Резервная копия читается только на том же компьютере/профиле Windows (мастер-ключ привязан к DPAPI).
* `node:sqlite` в Node 24 помечен как экспериментальный; других нативных зависимостей нет.
* Нет автообновления и подписи кода; интерфейс только на русском.
* Репозиторий: пуш в GitHub из этой сессии **не удался** (HTTP 403 — у сессии нет доступа к `tegrapubg-lab/tegra`); коммиты есть в локальной ветке
  `claude/istanbul-earnings-idea-xhhs0m`.
