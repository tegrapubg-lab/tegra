# Tegra Flow

Локальная платформа автоматизации рабочих процессов (аналог n8n) для Windows: визуальный редактор,
реальный движок исполнения, интеграции (HTTP, Telegram), ИИ-агенты. Одно приложение, один пользователь,
без регистрации и внешнего сервера. Node.js, Docker, PostgreSQL и Redis **не нужны**.

> Статус и что именно проверено — в [STATUS.md](STATUS.md). Архитектура и критерии — в [PLAN.md](PLAN.md).
> Старый чат `discord-lite`, который лежал в репозитории, сохранён в `legacy/discord-lite/`.

## Установка (для пользователя)

1. Запустите `Tegra-Flow-Setup-<версия>.exe` → выберите папку → установщик создаст **ярлык на рабочем столе** и в меню «Пуск».
2. Откройте «Tegra Flow». Данные хранятся в `%APPDATA%\Tegra Flow\` (не в папке установки), поэтому
   переживают обновление и переустановку. При удалении программы данные **не** удаляются.

Установщик собирается командой `npm run dist:win` на Windows либо workflow
[`windows-installer`](.github/workflows/windows-installer.yml) (GitHub Actions → артефакт `Tegra-Flow-Setup`).
Подробности и ограничения — раздел «Сборка».

## Быстрый старт

1. **Сценарии → «＋ Новый сценарий»**. Слева — палитра узлов (клик добавляет узел справа от выбранного, либо перетащите).
2. Соедините узлы, перетягивая точки (выходы справа → входы слева). Циклы редактор не даст создать.
3. Выберите узел — справа форма его параметров. Ошибки (обязательные поля, неверные связи) видны сразу.
   Значения поддерживают выражения `{{ $json.price * 2 }}`.
4. **Ctrl+S** — сохранить, **▶ Запустить** — выполнить (или «с данными…» — передать JSON).
   Узлы подсвечиваются по статусам; внизу — шаги с входными/выходными данными (JSON или таблица), журналом и ошибками.
5. «Включён/Выключен» — активация автоматических триггеров (расписание, webhook, Telegram).
6. **Примеры** — готовые сценарии, в т.ч. бизнес-пример «Одежда → маркетолог → сценарист → редактор → подтверждение → Telegram».

### Трей, закрытие и выход

* Кнопка **✕ окна** сворачивает приложение в трей — **автоматизация продолжает работать** (расписания, webhook, Telegram).
  При первом закрытии показывается уведомление об этом.
* **Полный выход** — меню значка в трее («Выйти полностью…») или Настройки. Если есть включённые сценарии, приложение
  предупредит, что автоматизация будет остановлена.
* **Автозапуск при входе в Windows** (свёрнутым в трей) — Настройки или меню трея. По умолчанию выключен.

## Узлы

| Узел | Назначение |
|---|---|
| Ручной запуск | Старт кнопкой; можно передать входной JSON |
| Webhook | Локальный адрес `http://127.0.0.1:<порт>/hook/<id>`, обязательный секрет в заголовке `X-Webhook-Secret` |
| Расписание | Интервал или cron (5 полей) с часовым поясом; политика пропущенных запусков |
| Telegram: сообщение | Получение сообщений бота через long polling (публичный адрес не нужен) |
| Поля (Set) | Создание/преобразование полей, типы, выражения; строки видят результат предыдущих строк |
| IF / Switch | Ветвление по условиям (до 4 правил + «Другое») |
| Разделить список | Массив из поля → отдельные элементы |
| Объединение веток | Явное слияние: «добавить» или «попарно»; режим «требовать обе ветки» |
| Повторить N раз | Безопасная замена циклам (циклы в графе запрещены) |
| Ожидание | Пауза на время/до даты; **состояние в БД, процесс не занят** |
| Вложенный сценарий | Запуск другого сценария; родитель ждёт в БД; глубина ≤ 5 |
| Результат сценария | Что возвращает вложенный сценарий/инструмент агента |
| Ждать решения пользователя | «Продолжить»/«Отклонить» в разделе «Подтверждения», тайм-аут по желанию |
| HTTP-запрос | Методы, заголовки, query, тело (JSON/текст/форма), авторизация (Bearer/Basic/заголовок), Idempotency-Key, лимиты |
| Telegram: отправить | Текст, файл по URL или текст как документ |
| Языковая модель | Один вызов модели через адаптер |
| ИИ-агент | Системная инструкция, модель, **ограниченный набор инструментов**, формат (текст/JSON), лимиты шагов/вызовов/токенов/времени, трасса вызовов |

Выражения: `{{ $json.поле.вложенное[0] }}`, `{{ $node["Имя узла"].json.x }}`, `$index`, `$run.id`, `$now`, арифметика, `?:`, `??`,
функции `round, upper, lower, trim, length, join, json, parseJson, replace, substring, min, max, isEmpty, first, last, …`.
Разбор собственный, **без eval/vm**; доступ к `constructor/__proto__` запрещён. Узла произвольного кода сознательно нет
(он появится только вместе с настоящей изоляцией).

### Правила выполнения графа

* Данные между узлами — массивы элементов `{json: {...}}`. Узел обрабатывает все элементы входа.
* Узел стартует, когда **все** входящие связи «разрешены»: источник завершился или пропущен. Связь «живая», если на выходе-источнике ≥ 1 элемента. Если живых связей нет — узел **пропускается**, пропуск распространяется дальше.
* Несколько связей в один вход складываются подряд; для явного слияния — «Объединение веток».
* Независимые ветки идут параллельно (по умолчанию до 4 узлов на запуск, до 4 запусков одновременно — настраивается).
* Для каждого запуска хранится **неизменяемый снимок сценария**: правка во время выполнения/ожидания его не меняет.
* Тайм-аут и повторы настраиваются на узле (по умолчанию тайм-аут 60 с, агент 300 с, 1 попытка). Задержка между попытками удваивается (≤ 5 мин).
* **Гарантии доставки: «как минимум один раз».** После падения/перезапуска неоконченный узел выполняется заново; внешние действия
  (HTTP, Telegram) могут повториться. Exactly-once **не обещается**. У HTTP-узла есть опция Idempotency-Key
  (`runId:nodeId:индекс`, одинаковый на всех попытках) — сервер должен её поддерживать.
* Восстановление: при старте просроченные задания возвращаются в очередь, узлы `running` → `pending`, ожидающие таймеры/подтверждения продолжаются.

### Расписания, сон и перезапуск

Следующий запуск хранится в БД. Если запуск опоздал больше чем на 90 секунд (компьютер спал, приложение было закрыто),
он считается **пропущенным**; поведение — параметр узла «Пропущенные запуски»:
**Пропустить** (по умолчанию) или **Выполнить один раз после возобновления** (всегда один, даже если пропущено много;
в данных `missed: true`). Часовой пояс — IANA (`Europe/Istanbul`), cron вычисляется в нём, включая летнее время.

## Telegram

1. В Telegram откройте `@BotFather` → `/newbot` → получите токен вида `123456789:AAH…`.
2. В приложении: **Подключения → Добавить → Telegram-бот**, вставьте токен.
3. Узел **Telegram: сообщение** (триггер) получает сообщения через `getUpdates` (long polling) — публичный сервер не нужен.
   Включите сценарий. Напишите боту — появится запуск; в данных: `chatId`, `text`, `from`.
   Свой `chatId` можно увидеть в данных этого запуска.
4. Узел **Telegram: отправить** — укажите бота и `Chat ID` (например `{{ $json.chatId }}`).
5. **Один токен — один получатель:** второй включённый сценарий с тем же ботом не активируется (понятное сообщение). Если бот
   опрашивается другим приложением, Telegram возвращает 409 — приложение покажет это в статусе.
   Если у бота настроен webhook, `getUpdates` не работает — снимите его через `deleteWebhook`.

## Модели ИИ

**Подключения → Провайдер ИИ**:

* **OpenAI-совместимый** — `Базовый URL` + ключ + модель. Подходит для OpenAI (`https://api.openai.com/v1`), OpenRouter
  (`https://openrouter.ai/api/v1`), Ollama (`http://localhost:11434/v1`, ключ не нужен), LM Studio (`http://localhost:1234/v1`),
  Google Gemini через совместимый endpoint и др. Адрес провайдера задаётся пользователем явно, поэтому локальные адреса разрешены.
* **Anthropic (Claude)** — ключ + модель (адрес по умолчанию `https://api.anthropic.com`).
* **Демо (без ключа)** — детерминированный шаблонный ответ с пометкой «ДЕМО-ОТВЕТ». **Это не настоящая модель**; нужен,
  чтобы проверить сценарий целиком без ключей.

Ключи вводятся только через интерфейс и шифруются на диске. Адаптеры подключаемые (`src/engine/llm.ts`, `LlmRegistry.register`).

**ИИ-агент:** инструменты — `Текущее время`, `Калькулятор`, `HTTP GET` (только публичные адреса) и любые ваши **вложенные сценарии**
(агент передаёт им входной JSON). Всё, что не отмечено, вызвать нельзя. Лимиты: шаги, число вызовов инструментов, токены, тайм-аут узла.
В результате — поле `agent.trace`: шаги, вызовы инструментов, аргументы и результаты (без «внутренних рассуждений»). Результат одного
агента передаётся следующему обычными полями (`{{ $json.marketing }}`). Формат «JSON» разбирается и проверяется (одна попытка исправления).

## Бизнес-пример

**Примеры → «Бизнес: одежда → маркетолог → сценарист → редактор → подтверждение → Telegram»** (файл
[`examples/clothing-pipeline.json`](examples/clothing-pipeline.json)): данные об одежде → агент-маркетолог → агент-сценарист → агент-редактор →
**подтверждение пользователем** → отправка в Telegram. При установке создаётся демо-провайдер ИИ; для настоящих ответов
замените его своим в узлах-агентах. Выберите Telegram-бота и впишите `chatId` в узле «Данные об одежде».

**Монтаж видео и публикация в TikTok НЕ подключены.** Сценарий явно записывает `tiktok_status: not_connected` и
сообщает, что видео не создавалось и не публиковалось. Успешная публикация не изображается.

## Webhook: локальный адрес и публичное подключение

Webhook слушает **только `127.0.0.1`** и недоступен из интернета. Запрос:

```
curl -X POST http://127.0.0.1:47821/hook/<id> -H "X-Webhook-Secret: <секрет>" -H "Content-Type: application/json" -d '{"customer":"Али"}'
```

Ответ `202 {accepted, runId}` — запуск выполняется асинхронно. Неверный секрет — `401` (после 20 неудач с одного адреса — `429`).
Чтобы принимать запросы извне, **отдельно** поднимите туннель (Cloudflare Tunnel, ngrok и т. п.) на порт приложения и укажите его
адрес в Настройках — он отобразится в узле. Приложение само ничего не открывает в интернет. Порт по умолчанию 47821; если занят,
выбирается свободный (адреса webhook тогда меняются — приложение предупредит в журнале).

## Безопасность

* Electron: `contextIsolation`, `sandbox`, `nodeIntegration: false`, строгий CSP, запрет навигации/окон/вебвью/разрешений;
  preload отдаёт два метода; main принимает только белый список методов, проверяет отправителя и размер.
* Движок — отдельный процесс; сценарии в UI не исполняются. HTTP API на `127.0.0.1`, Bearer-токен (знает только main), проверка `Host` (DNS-rebinding).
* Секреты подключений: AES-256-GCM; мастер-ключ защищён **Windows DPAPI** (`safeStorage`). Не попадают в экспорт, журналы, историю запусков,
  ответы API. Известные значения секретов и поля `Authorization/token/password/…` маскируются как `***`.
  **Ограничение:** секрет, вписанный вручную в параметр узла (а не в «Подключения»), лежит в определении сценария открытым текстом,
  но маскируется в показах, истории и экспорте — для секретов используйте «Подключения».
* HTTP-узел: локальные/приватные/link-local/метаданные облака **запрещены по умолчанию**, включается явной галочкой узла.
  Проверка выполняется при соединении (защита от DNS-rebinding), перенаправления проверяются на каждом шаге (≤ 5), заголовок
  `Authorization` не уходит на другой origin, логин в URL запрещён, размер ответа ограничен (по умолчанию 5 МБ).
* Лимиты: тело webhook 1 МБ, API 12 МБ, результат узла 5 МБ / 10 000 элементов, импорт файлов 10 МБ.

## Данные и резервные копии

* БД SQLite `%APPDATA%\Tegra Flow\data\tegra.sqlite`, миграции в `src/engine/migrations.ts` (применяются автоматически, один раз).
* **Настройки → Резервные копии**: ручная копия/восстановление (`.sqlite`); автокопия раз в сутки в `backups\` (последние 7).
  Перед восстановлением текущая база сохраняется. Секреты в копии зашифрованы и читаются только на этом компьютере и в этом профиле Windows
  (на другом компьютере подключения помечаются «не читается» — введите секреты заново, сценарии и история сохранятся).
* Экспорт/импорт сценария — JSON без секретов и без ссылок на подключения; адреса webhook при импорте генерируются заново.

## Разработка и сборка

Требуется Node.js 24+ (в готовом приложении он встроен в Electron).

```bash
npm install
npm test               # собирает движок и запускает 69 автотестов (vitest)
npm run typecheck
npm run build          # dist/engine, dist/main, dist/renderer
npm start              # собрать и запустить Electron
npm run ui-e2e         # (Linux, нужен xvfb) сквозной тест настоящего окна Electron: сборка сценария мышью, запуск, перезапуск, выход
npm run dev:engine     # движок без Electron: HTTP API на 127.0.0.1:47821 (токен печатается/берётся из TEGRA_API_TOKEN)
npm run examples       # пересоздать examples/*.json
npm run dist:win       # установщик NSIS → release/Tegra-Flow-Setup-<версия>.exe
```

**Установщик собирайте на Windows** (или в GitHub Actions — готовый workflow): при этом в `.exe` встраиваются значок и метаданные.
При сборке на Linux/macOS electron-builder требует рабочий `wine`; без него готовится только каталог `release/win-unpacked`
(настоящий Windows-бинарник `Tegra Flow.exe`), а финальный NSIS-шаг не выполняется. Если `dist:win` на Windows ругается на
создание символических ссылок при распаковке `winCodeSign`, запустите терминал от администратора или включите «Режим разработчика».

Структура: `src/shared` (формат сценария, спецификации узлов, валидация) · `src/engine` (БД, очередь, исполнитель, узлы, API, расписания,
Telegram, LLM) · `src/main` (Electron: окно, трей, процесс движка, IPC) · `src/renderer` (React + React Flow) · `tests` · `examples`.
Движок запускается и без Electron — это основа будущего серверного режима. Новый тип узла = спецификация в `src/shared/specs.ts`
+ исполнитель в `src/engine/nodes/` (реестр проверяет, что у каждого узла есть исполнитель).
