# PLAN — Tegra Flow

Локальная платформа автоматизации (аналог n8n) для Windows: визуальный редактор, движок исполнения,
интеграции, ИИ-агенты. Одно приложение Electron, без внешних серверов.

## Архитектура

```
┌─────────────── Electron ────────────────┐
│ renderer (React + React Flow)           │  sandbox, contextIsolation, без Node
│   └─ window.tegra.call(метод, параметры)│  ограниченный preload
│ main (трей, окно, автозапуск, диалоги)  │  валидирует каждое IPC-сообщение (zod)
│   └─ utilityProcess ──────────────┐     │  хранит мастер-ключ (DPAPI/safeStorage)
└───────────────────────────────────┼─────┘
                                    ▼
        ENGINE (отдельный процесс, чистый Node, без Electron)
        HTTP 127.0.0.1:порт  /api/* (Bearer-токен)   /hook/<id> (секрет)
        ├ db        SQLite (node:sqlite) + миграции + бэкап
        ├ queue     таблица jobs: захват с lease, heartbeat, восстановление
        ├ executor  исполнение графа по сохранённому состоянию (run_nodes)
        ├ nodes/    реестр типов узлов (spec + execute + resume)
        ├ triggers  расписания (cron/интервал, часовой пояс), webhook, Telegram long-polling
        ├ llm/      адаптеры: openai-compatible, anthropic, demo
        └ secrets   AES-256-GCM, маскирование
```

* `src/shared` — формат сценария, типы, спецификации узлов, валидация (используется UI, main и engine).
* Движок запускается и без Electron (`node dist/engine/main.js`) — это путь к будущему серверному режиму.
* UI не исполняет сценарии. main только проксирует белый список методов в engine.

## Модель данных и правила исполнения (контракт)

* Элемент данных: `{ json: объект }`. Узел получает на вход массив элементов, выдаёт массивы по именованным портам.
* Узел запускается, когда все входящие рёбра «разрешены» (источник завершён/пропущен). Ребро «живое», если на порту
  источника ≥1 элемента. Если все входящие рёбра мёртвые — узел пропускается (`skipped`), пропуск распространяется.
* Несколько рёбер в один вход `main` — элементы добавляются в порядке рёбер. Явное объединение — узел «Объединение».
* Независимые ветки идут параллельно (лимит `nodeParallelism`, по умолчанию 4); запусков одновременно — `maxConcurrentRuns`.
* Циклы в графе запрещены (проверка при сохранении/запуске). Повторение — узел «Повторить N раз» / «Разделить список».
* Каждый запуск хранит **неизменяемый снимок** сценария. Состояние узлов — в таблице `run_nodes` (после каждого узла).
* Ожидание (таймер, подтверждение, вложенный сценарий) — статус `waiting` в БД, процесс не занят.
* Повторы: `maxAttempts`, `retryDelayMs` (≤5 мин, в процессе), тайм-аут узла. Доставка внешних действий — **at-least-once**;
  HTTP-узел умеет стабильный `Idempotency-Key`. Exactly-once не обещается.
* Восстановление: при старте просроченные lease → задания возвращаются в очередь, узлы `running` → `pending`.
* Выражения `{{ $json.a.b }}`, `{{ $node["Имя"].json.x }}` — собственный безопасный разбор, без eval/vm.

## Этапы и критерии готовности

| # | Этап | Критерий готовности |
|---|------|---------------------|
| 1 | Ядро: БД, миграции, очередь, исполнитель, узлы Manual/Set/IF/HTTP, HTTP API | Тест: ручной запуск → Set → IF → HTTP → результат в SQLite через очередь |
| 2 | Электрон-оболочка + UI: редактор, запуск, просмотр шагов | Окно открывается, сценарий собирается мышью, запускается, шаги видны (скриншот в Electron под xvfb) |
| 3 | Остальные узлы: Switch, Split, Merge, Wait, Subworkflow, Webhook, Schedule, Repeat, Result | Юнит-тесты ветвления/слияния, wait, подсценарий |
| 4 | Надёжность: retries, отмена, рестарт, расписания после сна | Тесты, включая kill -9 процесса движка |
| 5 | Интеграции: Telegram (long polling), LLM-адаптеры, ИИ-агент, подтверждение | Тесты на mock-серверах; примеры сценариев |
| 6 | Безопасность и данные: секреты, маскирование, SSRF, бэкап/восстановление | Тесты маскирования, SSRF, бэкапа |
| 7 | Упаковка: electron-builder NSIS, ярлык, трей, автозапуск | Установщик `.exe` собран; ограничения проверки на Windows описаны |
| 8 | Документация | README, STATUS, примеры, описание Telegram/моделей |

Вне объёма v0.1 (явно): узел произвольного кода (нужна настоящая изоляция), монтаж видео, публикация в TikTok,
публичный туннель, многопользовательский режим.
